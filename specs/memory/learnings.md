## 2026-07-12 — Demo frontend renders only pipeline-produced artifacts (spec 002, `apps/demo-web`)

- **What was built:** A static Vite/React SPA (ADR-0003 records the Next.js deviation) whose only
  data source is `public/demo-data.json`, generated by `tools/e2e/src/demo-data.ts` running the
  real in-memory pipeline (ingest HTTP → worker → dashboard reads) over the seed corpus on every
  `predev`/`prebuild`. The generator exits non-zero *without writing* on any unexpected stage
  outcome, so a broken pipeline can't ship a healthy-looking demo; a spot-check test recomputes
  insights with the shared engine and asserts equality with the artifact (the anti-hard-coding
  guarantee, plus a jest architecture test since the repo has no ESLint).
- **Demo-steering beats fixture-forking:** the "processing", "on phone only", and
  "failed-validation" states aren't special fixtures — they're the same seed sessions steered at
  generation time (withheld from the worker / never uploaded / blob corrupted post-ingest), so
  the e2e suite still processes all of them normally.
- **Emergent low confidence is tunable:** the engine's reliability rule (mean cycle confidence
  ≥0.6, gap-overlap cycles = 0.4) means a session with 120ms mid-stance dropouts on ⅔ of
  left-foot stances lands at ~0.57 (unreliable) while lighter right-foot gaps land at ~0.77
  (reliable-but-degraded) — probe the engine first, then encode the arithmetic in the fixture
  comment.
- **Determinism discipline for generated artifacts:** inject the worker clock
  (`nowMs: sessionStart + duration + 60s`) and pin ingest-minted correlation IDs to session IDs;
  a byte-identical-across-runs test keeps it honest.
- **jsdom gotchas:** react-router v7 needs `TextEncoder` polyfilled in a jest `setupFiles`; nav
  tab labels that duplicate view headings make `getByText` ambiguous — query headings by role.
- **Result:** 331 tests green repo-wide; Claude Design prototype iteration (Req. 13) and the
  manual viewport pass remain user actions (checklist in `apps/demo-web/README.md`).

## 2026-07-07 — Seed data + full-pipeline software e2e (`tools/e2e`)

- **What was built:** A new `tools/e2e` workspace with (1) a deterministic seed corpus — 3 athletes + 1 coach roster with sharing grants, 7 contract-valid synthetic sessions (clean run w/ matching on-phone result; labeled `normal`/`favor-left-leg`/`favor-right-leg` training sessions; BLE-dropout capture; tampered on-phone result; non-sharing athlete as access probe) plus one invalid fixture — and (2) a 15-test e2e suite driving ingest → worker → dashboard → dataset snapshot → training entirely on the in-memory adapters. Regenerate fixtures with `npm run seed --workspace @smart-sneaker/e2e` (gitignored; byte-identical across runs).
- **Pattern that paid off:** Because every service ships `ports.ts` + in-memory adapters and separates `buildServer(deps)` from `main.ts` wiring, the e2e wires production-shaped services with zero production code changes — the blobs/events/records ingest writes are literally what the worker, dataset store, and trainer read.
- **Seed-fixture discipline:** fixed v4-shaped UUIDs (`00000000-0000-4000-8000-<n>`) + fixed epoch timestamps + self-validation against `SessionSchema` at build time; per-session expectations (`expectFlaggedForReview`, labels) travel in the manifest so tests iterate it rather than hardcode.
- **Monorepo gotcha:** cross-workspace TS-source resolution must agree in three places — package `main: src/index.ts`, jest `moduleNameMapper`, tsconfig `paths` — and `ts-node` needs `-r tsconfig-paths/register` to honor `paths`.
- **Result:** 257 tests green repo-wide (242 existing + 15 new); pushed as `fc5abf3` on `feat/spec-001-t8-t14`.
