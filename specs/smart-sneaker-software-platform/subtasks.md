# Subtasks: Smart Sneaker — Software Platform

> Source: [spec.md](./spec.md) · Generated by `/subtasks` · Date: 2026-06-27

**Goal:** Break the Smart Sneaker software-platform spec into an ordered set of buildable subtasks that deliver a thin end-to-end slice first (record → process → view insights), then layer on cloud, access control, dataset, and ML.

## Subtasks

1. **Lock the session/BLE contract & fixtures** — Pin down the raw-packet schema, sample rate, channel layout, and timestamp source as a versioned session-data contract, and capture real or synthetic sample sessions (including one asymmetric, one varied-pace) to drive every downstream test. (dep: —)

2. **Define the canonical session data model** — Specify the on-disk/in-transit shape of a recorded raw session and its result envelope (insights + confidence + version tags), shared by app and cloud. (dep: 1)

3. **Build BLE pairing & connection-state UX** — Discover, pair, and show live connection status with an instrumented-shoe device. (dep: 1) [P]

4. **Implement reliable BLE ingest into a recorded session** — Receive the packet stream and assemble a complete, time-synced session (pressure + motion, L/R aligned). (dep: 2, 3)

5. **Add capture-quality detection** — Detect and surface dropped packets / disconnects / low signal during a session rather than silently corrupting it. (dep: 4)

6. **Persist sessions locally before processing/upload** — Durably store a recorded session so it survives app restart and a failed upload. (dep: 2, 4)

7. **Define the sport-profile contract** — Declarative profile (sensors, segmentation strategy, feature set, model ref) that the pipeline reads; ship the running profile. (dep: 2)

8. **Build the gait-segmentation engine (single source of truth)** — Segment a session into foot strikes and emit a segmentation-quality measure, as a shared library runnable identically on client and cloud. (dep: 2, 7)

9. **Build the running insights engine** — Compute the four insights (balance, per-foot contact time, cadence, strike type), each with a confidence/quality signal. (dep: 8)

10. **Add graceful degradation to the pipeline** — Return the insights that are reliable and clearly flag the unreliable/uncomputable ones instead of failing the whole session. (dep: 9)

11. **Verify client/cloud parity** — Shared-fixture test proving identical insights regardless of execution tier. (dep: 9) [P]

12. **Implement calibration flow & profile** — Guide the user through calibration and apply a stored per-user/per-device profile to subsequent sessions. (dep: 6) [P]

13. **Stand up auth, accounts & roles** — Authenticate users with athlete/coach roles, enforced server-side. (dep: —) [P]

14. **Build the idempotent ingest API** — Authenticated, encrypted session upload that won't duplicate sessions/results on re-upload, with auto-upload-on-reconnect from the app. (dep: 6, 13)

15. **Build the event-driven processing worker** — Consume the ingest event, run segmentation+insights server-side, persist structured results; retry-safe with permanent-failure marking. (dep: 9, 14)

16. **Persist raw + results with version tagging** — Retain raw sessions and stamp each result with its algorithm/model version. (dep: 2, 15)

17. **Support re-processing of past sessions** — Re-run a newer pipeline version over retained raw sessions to produce updated, version-tagged results. (dep: 16)

18. **Build athlete views** — Per-session insights (with confidence) and per-metric multi-session trends. (dep: 15) [P]

19. **Build coach views + sharing/access control** — Grant/revoke sharing; coach sees only sharing athletes; non-sharing data unreachable via API. (dep: 13, 18)

20. **Implement labeled-dataset tagging & versioned export** — Tag sessions with known conditions and expose them as a versioned, queryable training dataset. (dep: 16) [P]

21. **Build the model training/eval pipeline** — Train/evaluate on the labeled dataset, tracking model versions and metrics traceable to results. (dep: 20)

22. **Wire end-to-end observability** — Correlation ID from capture→upload→processing→result, RED metrics, and actionable failure/SLO alerts. (dep: 15) [P]

23. **Stand up the ground-truth validation harness** — Compare insights against the agreed ground-truth method and report agreement against the threshold. (dep: 9) [P]
